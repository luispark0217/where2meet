  - 탭바로 H(필터, 행, 모두 읽음) · I(칭호, 모임, 기록) · J(모든 행) 이동
  - D · E · G 버튼 전부, 강남구 E
  - 15개 화면에 딥링크로 들어가서 ← 누르기, 42초 동안 기다려 줄다리기 마감시키기
  - 다른 약속(m-lunch, m-bday, m-mt, m-study)에서 C의 모든 버튼
- 콘솔 에러: 없음. 딥링크 후 뒤로가기는 전부 앱 안에 머묾(지난 리포트 3번 해결 확인).
- 태그: **[구현]** = 우리 코드·목데이터에서 고칠 수 있는 것. **[디자인]** = `design-ref/*.png`에 이미 있는 것(디자이너에게 전달).

## P0 — 핵심 흐름에서 신뢰가 깨짐

### 1. N 장소 리스트 12곳 중 9곳이 "찾을 수 없어요"로 열림. 연남 로스터리도 그중 하나임 [구현]
- 화면: N → F
- 재현: C → 장소 리스트 보기 → `연남 로스터리`를 누름. `홍대 만두집`, `와우산 라운지 카페`, `합정 이자카야` 등도 눌러 봄.
- 결과: "장소를 찾을 수 없어요. 링크가 바뀌었거나 삭제됐을 수 있어요."가 뜸. N의 연남 로스터리 id는 `p-roastery`인데, F·E·O가 쓰는 id는 `p-roast`임. 나머지 8곳은 `placeKings`에 데이터가 아예 없음. F로 제대로 열리는 곳은 파스타집·와인바·LP바 3곳뿐임.
- 영향: 이 약속에서 투표 1등이고 "우리 왕좌"인 장소를 눌렀는데 삭제된 곳이라고 나옴. 앱에서 가장 중요한 장소가 깨진 링크처럼 보임.
- 제안: `tug.ts`의 id를 `p-roast`로 통일함. 왕이 없는 후보 장소는 F로 보내지 말고 "아직 왕이 없는 곳 · 첫 방문하면 왕" 상태를 보여줌. 최소한 목데이터라도 채움. 링크 대상이 없으면 행을 링크로 만들지 않음.

### 2. "모임 만들기"를 누르면 새 모임이 아니라 대학 동기 모임이 열림 [구현]
- 화면: Q → B
- 재현: Q에서 이름 `테스트팟`, 종류 `회사`를 고르고 모임 만들기를 누름.
- 결과: "모임을 만들었어요" 토스트가 뜨고 `/group/g-uni`로 감. 화면에는 대학 동기 모임, 6명, 2021년부터, 약속 24회가 나옴. A에도 새 모임이 없음(계속 4개). 이 상태에서 뒤로가기를 누르면 K 시트가 다시 열림.
- 영향: 내가 방금 입력한 이름이 사라지고 남의 모임 데이터가 보임. 가짜 동작인 줄 모르는 테스트 사용자는 버그라고 생각함.
- 제안: 목 API에서 입력값으로 새 Group을 만들어 `mock.groups`에 넣고 그 id로 이동함(멤버 = 초대한 3명, 약속 0회, 왕 0곳, 빈 약속 목록). 이렇게 못 하면 토스트를 "지금은 미리보기라 저장되지 않아요"로 바꾸고 원래 화면에 머묾.

### 3. 투표로 확정해도 아무것도 바뀌지 않음. 공유 시트를 닫으면 투표 화면으로 돌아가고 내 표도 원래대로 돌아감 [구현]
- 화면: P → S → P / C
- 재현: P에서 동교동 와인바에 투표함 → `이 장소로 확정`("연남 로스터리로 확정했어요") → S → ✕.
- 결과:
  - S를 닫으면 **P로 돌아옴**. 내 표는 다시 연남 로스터리에 있고 "확정"은 사라짐.
  - S 미리보기는 `9/25 (금) 19:00 · 홍대입구역`이라 확정한 장소가 없음.
  - C로 돌아가도 여전히 `② 장소 정하는 중 · 줄다리기 중 0:42 · 홍대입구역`임.
- 영향: 이 서비스 흐름의 끝(시간 → 장소 → 확정 → 공유)에 실제 결과가 남지 않음. 친구에게 보내는 카드에 가게 이름이 없음.
- 제안:
  - 확정 후에는 `nav('/meet/:id/share', { replace: true })`로 P를 히스토리에서 뺌.
  - 확정한 장소를 목 상태(meeting.placeName, stage `confirmed`)에 저장해서 C·S·B 카드가 모두 이 값을 쓰게 함.
  - S의 whenWhere는 `9/25 (금) 19:00 · 연남 로스터리`처럼 확정 장소에서 만듦.

### 4. 줄다리기 결과(합정역)가 다른 화면 어디에도 반영되지 않음 [구현 + 디자인]
- 화면: R ↔ C / N / P / S
- 재현: M에서 당기기 → R("합정역 도착!", 내 이동시간 28→21분) → 뒤로 → C.
- 결과:
  - C는 여전히 `홍대입구역 · 평균 24분 · 최대 차이 7분`임.
  - N은 "홍대입구 주변" 추천이고, S는 "홍대입구역"임.
  - R의 최대 차이는 14분인데 C는 7분임.
- 영향: 줄다리기를 한 의미가 없어 보임. "당겨 봤자 소용없네"라는 인상을 줌.
- 제안: [구현] C의 중간 지점 카드가 tug 보드의 현재 step(`bubble` 또는 역 이름, `gapMin`)을 읽게 함. [디자인] N·S에 "지금 중간 지점: ○○역" 기준을 표시하는 방식을 디자이너와 정함.

### 5. 금요일 저녁 말고 다른 약속에서는 C의 버튼 3개가 모두 "삭제됐을 수 있어요"로 감 [구현]
- 화면: C(m-lunch, m-bday, m-mt, m-study) → M / N / S
- 재현: 회사 점심팟 → `금요일 점심` → `↔ 줄다리기`, `장소 리스트 보기`, `약속 확정하고 공유하기`, 우측 상단 `↗`를 누름. 생일 파티·10월 MT의 ↗와 장소 리스트도 같음.
- 결과: 모두 "줄다리기/장소 리스트/약속을 찾을 수 없어요. 링크가 바뀌었거나 삭제됐을 수 있어요." N 헤더는 ` · 장소 리스트`처럼 제목 없이 점만 남음.
- 영향: 방금 보던 약속이 삭제된 것처럼 보임. 무서운 에러 문구가 흔하게 뜸.
- 제안: tug·places·share 목 API가 모든 약속에 기본 데이터를 돌려주게 함(최소 share는 제목·시간·역으로 만들 수 있음). 데이터가 없는 단계는 버튼을 숨기거나 `soon()`으로 처리함. 또 "없음" 문구와 "준비 중" 문구를 구분함.

### 6. 줄다리기 타이머가 화면에 들어갈 때마다 0:42로 다시 시작됨 [구현]
- 화면: C / M / R / O
- 재현: C에서 5초 기다림(0:37) → 줄다리기 → M은 **0:42** → 채팅 → O **0:42** → 뒤로 → R **0:38**.
- 영향: 제한시간 60초짜리 게임의 긴장감이 사라짐. 들어갔다 나오면 시간이 늘어나는 게 눈에 보임.
- 제안: `endsAt`을 목 모듈에서 한 번만 정함(예: 모듈 로드 시 `Date.now()+42_000`). C·M·O가 같은 값을 쓰게 함. 끝난 뒤에는 "새로 시작" 버튼(개발용)으로만 초기화함.

## P1 — 눌렀는데 엉뚱한 곳으로 가거나 상태가 사라짐

### 7. "여기서 약속 잡기"와 "약속 만들기 시작"이 이미 있는 '금요일 저녁'을 엶 [구현]
- 화면: L → K → C, 그리고 A → + → K → C
- 결과:
  - L(동교동 와인바 도전)에서 `여기서 약속 잡기`를 누르면 장소 정보 없이 K가 열림. 시작하면 **홍대입구역의 금요일 저녁**이 열림.
  - K에서 대학 동기 모임이 아닌 모임을 고르면 "준비 중" 토스트만 뜸.
  - K의 `새 약속 잡기` 카드(→ 화살표 있음)를 누르면 눈에 띄는 반응이 없음. 칩 영역에 포커스만 감.
- 영향: "새 약속"을 만들었는데 옛 약속이 나옴. 도전하려던 장소도 사라짐.
- 제안: K에 `?place=p-wine`을 넘겨서 시트 상단에 "동교동 와인바에서" 칩을 보여줌. 시작하면 빈 `m-new`(time 단계, 10월 MT 모양)로 이동함. 새 약속 잡기 카드는 누를 수 없는 선택 표시로 바꾸거나, 누르면 바로 시작하게 함.

### 8. 우리 모임이 왕인 장소에서 "도전하기"를 누르면 "대학 동기 모임 VS 대학 동기 모임"이 나옴 [구현]
- 화면: F(p-roast) → L
- 결과: 현재 왕 대학 동기 모임 23회 VS 내 모임 대학 동기 모임 23회, "지금은 우리가 왕"이 나옴. 규칙 안내는 그대로 나옴.
- 제안: F에서 `king.group.id === myGroupId`이면 도전하기 대신 `왕좌 지키기`(2위와 차이 보여주기)를 둠. L의 VS 오른쪽에는 2위 모임을 보여줌("필름 동아리가 4회 차이로 추격 중").

### 9. F의 "다른 왕좌" 카드 대부분이 찾을 수 없는 곳이고, 1위가 아닌 곳도 섞여 있음 [구현 + 디자인]
- 화면: F → F
- 결과:
  - p-roast의 `합정 이자카야`, `성수 달빛포차`와 p-pasta의 `시청 국밥집`, p-comic의 `레드버튼 홍대점`을 누르면 "찾을 수 없어요"가 뜸.
  - "필름 동아리의 다른 왕좌"에 `상수 LP바 2위`가 있음. "영화 동호회의 다른 왕좌"는 `홍대 시네마 2위` 하나뿐임.
- 제안: [구현] 누락된 placeKings를 추가함. [디자인] 목록 제목에 맞게 1위만 넣거나, 제목을 "자주 가는 곳"으로 바꿈(시안 F가 2위를 넣고 있음).

### 10. 줄다리기가 끝나도 아무 일이 없음 [구현]
- 화면: M / C
- 재현: M에서 42초 기다림.
- 결과:
  - 타이머 칩이 `마감`으로 바뀌고 당기기 버튼이 흐려질 뿐임. 결과(최종 지점)도 다음 단계 안내도 없음. "꾹 누르고 있으면 내 쪽으로 한 칸씩" 문구가 그대로 남음.
  - C는 "줄다리기 끝"인데 `↔ 줄다리기` 버튼이 계속 켜져 있고 단계도 그대로임.
- 제안: 끝나면 아래 판을 "합정역으로 결정! · 최대 차이 14분" + `장소 투표하러 가기`(P) 버튼으로 바꿈. 안내 문구는 숨김.

### 11. 줄다리기 화면에 다시 들어가면 내가 당긴 기록이 사라짐 [구현]
- 화면: R → C → M, O의 `보러가기`
- 결과: 당긴 상태가 URL(`?pulled=1`)에만 저장돼 있음. C의 `↔ 줄다리기`나 O의 `보러가기`로 다시 들어가면 M(당기기 2번 남음, 24분)으로 돌아감. 한 번 더 당길 수 있어서 기회가 늘어남.
- 제안: 당긴 횟수를 목 모듈 상태에 저장함(`tugApi.pull`이 pullsUsed를 늘림). 화면은 서버 값을 따르고, `?pulled=1`은 R 딥링크용으로만 남김.

### 12. 투표에서 "은"이 두 명으로 보이고, 그중 한 명은 모임에 없는 사람임 [디자인 + 구현]
- 화면: P
- 재현: P에서 서교동 파스타집을 누름.
- 결과: 파스타집에 `은 은 2표`가 뜸. 둘 다 라임색 '은'이라 내가 두 번 투표한 것처럼 보임. 한 명은 목데이터가 만든 `은호`인데 대학 동기 모임 멤버(은수·지민·도윤·서아·하준)가 아님. 시안 P에서도 파스타집 투표자가 '은'임.
- 영향: 표를 조작한 것처럼 보임.
- 제안: [디자인] 파스타집 투표자를 하준(보라)으로 바꿈. [구현] `eunho`를 `ha`로 바꿈.

### 13. 알림 3건이 다른 화면과 서로 맞지 않음 [디자인 + 구현]
- 화면: H → F / C / B
- 결과:
  - `왕좌를 빼앗겼어요! 연남 로스터리 · 필름 동아리가 1회 차이로 역전` → 눌러서 열린 F에서는 **대학 동기 모임이 17일째 왕, 23 vs 19**임.
  - `약속 초대 · 필름 동아리 · 10월 MT` → 열리는 곳은 **대학 동기 모임의 10월 MT**임(필름 동아리의 약속은 "10월 정기 상영회").
  - `대학 동기 모임이 서교 만화방의 왕이 됐어요` → "서교 만화방"이라는 곳은 없음. 홍대 만화방의 왕은 보드게임 모임이고 우리는 3위(5회)임. 게다가 이 알림을 누르면 장소가 아니라 모임 화면으로 감.
- 제안: [디자인] 문구를 데이터에 맞춤(예: "동교동 와인바 · 필름 동아리와 2회 차이", "필름 동아리 · 10월 정기 상영회", 실제로 우리가 1위인 장소). [구현] a-4는 `/meet/m-film`으로, a-5는 해당 장소 F로 연결함.

### 14. 강남구를 누르면 "왕좌 0곳"이 나옴. 지도에서는 31곳이었음 [구현]
- 화면: D → E(d-gangnam)
- 결과: 헤더에 `강남구 · 왕좌 0곳`, 본문에 "확대 지도는 준비 중이에요"가 나옴. D의 원에는 31이라고 적혀 있었음.
- 제안: 준비 안 된 지역은 개수를 빼거나 D의 count(31곳)를 그대로 보여줌.

### 15. C의 "약속 확정하고 공유하기"가 투표를 건너뛰고 바로 공유 시트를 엶 [구현 + 디자인]
- 화면: C → S
- 결과: 줄다리기가 아직 진행 중(0:37)인데 "확정"이라는 버튼이 투표 없이 S를 엶. 아무것도 확정되지 않음. m-lunch처럼 "장소 투표 중"인 약속도 똑같음.
- 제안: 장소가 정해지기 전(tug/place)에는 버튼을 `장소 투표하기`(→ P)로 바꿈. 확정은 P에서만 하게 함. 시안 C의 버튼 이름은 디자이너와 다시 정함.

## P2 — 숫자·날짜·문구가 어긋남

### 16. 요일과 날짜가 서로 맞지 않음 [구현]
- 화면: B / C
- 결과(2026년 달력 기준):
  - `금요일 점심 · 9/26`: 9/26은 토요일임. C에서는 "금 12:00 확정"인데 시간표에는 17–22시만 있고, 금 17시 칸에 흰 테두리가 있음.
  - `생일 파티 · 10/12`: 월요일임. C는 "토 20:00 확정"인데 시간표는 9월 25–27일임.
  - `스터디 뒤풀이 9/12`(토)는 "금 19:00", `여름 방학 번개 8/3`(월)은 "금 20:00"으로 나옴.
- 제안: 약속마다 availability의 days/hours를 확정된 날짜에 맞춤. 점심은 11–14시를 씀.

### 17. 약속 인원이 화면마다 4명·5명·6명으로 다름 [디자인]
- 화면: M / C / O / P / B
- 결과:
  - 줄다리기와 C 지도는 4명(은·지·도·서)임.
  - O 헤더는 "대학 동기 모임 · 6명", P는 "6명 중 4명 투표"임.
  - B 아바타는 5명인데 텍스트는 "6명"임.
- 제안: "이 약속 참여자 4명"과 "모임 6명"을 구분해서 적음(O: "4명 참여 · 대학 동기 모임", P: "4명 중 4명 투표").

### 18. 필름 동아리 인원이 A·B에서는 8명, I에서는 9명임 [디자인]
- 제안: 시안 I를 8명으로 맞춤. 우리 쪽은 `me.ts`의 myGroups가 `mock.groups`에서 memberCount를 가져오게 해서 숫자를 한 곳에서 관리함.

### 19. M의 "지민님이 성수 쪽으로 한 칸 당겼어요"가 지도와 모순됨 [디자인]
- 결과: 같은 화면에서 지민은 `+2분`(멀어짐)이고 지점은 합정역 쪽으로 이동 중임. 지민이 자기 쪽으로 당겼다면 지민의 시간이 줄어야 함. R의 "내가 한 칸 더 당겼어요"는 점 색이 내 색(라임)이 아니라 지민 색(노랑)임.
- 제안: [디자인] M 소식은 "서아님이 한 칸 당겼어요"처럼 지도와 맞는 문장으로 바꿈. [구현] R의 news color를 `var(--color-lime)`으로 바꿈.

### 20. 줄다리기 시작 알림의 "60초 안에 당겨주세요"가 실제와 다름 [디자인]
- 결과: 타이머는 0:42에서 시작하고 32분 전에 온 알림인데 아직 진행 중임. 또 J에서 `줄다리기 시작 알림`이 기본으로 꺼져 있는데 이 알림을 받음.
- 제안: 문구를 "마감 전에 당겨주세요"로 바꿈. 목 설정의 tug 기본값을 true로 바꿈.

### 21. 마이의 "가장 많이 간 곳 · 홍대입구 14회"가 장소가 아니라 역 이름이고, 눌러도 준비 중임 [디자인]
- 결과: 같은 사람의 모임은 동교동 와인바만 29회 갔음. "홍대입구"는 줄다리기의 중간 지점(역)이라 "곳"과 뜻이 섞임.
- 제안: 실제 장소(예: "동교동 와인바 · 14회")를 넣음. [구현] 누르면 그 장소의 F로 보냄.

### 22. B의 "진행 중" 탭에 "완료"된 스터디 뒤풀이가 있음 [디자인]
- 제안: 지난 탭으로 옮김(목데이터 `bucket: 'past'`). 시안 B는 진행 중 카드 4장 레이아웃이 필요해서 이렇게 넣은 것으로 보임. 대신 "장소 투표 중" 카드를 쓰는 것을 제안함.

### 23. N의 서교동 파스타집에 왕 표시가 없음. E·F에서는 회사 점심팟이 왕임 [디자인]
- 제안: 시안 N에 `왕: 회사 점심팟` 태그를 추가함(우리 목데이터에도 kingGroupName 추가).

### 24. N의 필터·정렬·찜이 장소를 봤다 돌아오면 전부 초기화됨 [구현]
- 재현: N에서 가까운 순 정렬, 파스타집 찜(♥4) → 파스타집 F → 뒤로.
- 결과: 취향순으로 돌아가고 ♥3이 됨. 찜을 "취소한" 것처럼 보임.
- 제안: 찜은 `tugApi.like`가 목 모듈 상태에 저장함(알림 읽음처럼). 정렬·필터는 URL 쿼리(`?sort=walk&cat=식당`)에 저장함. N의 `≡` 아이콘은 햄버거 메뉴처럼 보이므로 "취향순 ▾" 같은 텍스트 칩으로 바꾸는 것을 권함.

### 25. 채팅의 빠른 답장 "곧 도착 · 5분만"이 지금 상황과 맞지 않음 [디자인]
- 결과: 장소를 정하는 중(약속 당일 전)인데 도착 인사 문구가 나옴. 누르면 확인 없이 바로 전송됨.
- 제안: 단계별로 빠른 답장을 바꿈. 줄다리기 중에는 "나 좀 봐줘ㅠ · 투표 올려줘 · 여기 어때?", 당일에는 "곧 도착 · 5분만"을 씀.

## 잘 된 점 (유지)
- 딥링크 후 ←와 시트 닫기가 모두 상위 화면으로 감(C만 모임 B가 아니라 홈으로 감. 여유가 있으면 fallback을 `/group/:groupId`로 바꿈).
- 알림 읽음, 설정 토글, 채팅에 보낸 메시지는 화면을 오가도 유지됨.
- 꾹 누르기 당기기가 한 번만 동작함. 당기기를 다 쓰거나 한도에 걸리거나 마감되면 각각 알맞은 토스트가 뜸.
- K·S 시트의 딤·✕·Esc 닫기가 정상 동작함.
